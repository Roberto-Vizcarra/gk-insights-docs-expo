Adoption Score = min(Primary + 0.25 × Cursor, 100) × MaturityFactor

At a glance

The Agent Adoption Score is the dashboard's headline answer to "is this developer using AI?" It combines four dimensions of usage — daily consistency, time-of-day spread, prompt volume, and output tokens — across every AI tool the developer has access to. Higher means more consistent, deeper use.

It is normalized against your organization's own 90th-percentile usage, so the bar is your team, not an industry average. The score is descriptive, not evaluative: a senior developer on a quarter-long migration may read as Emerging because the work doesn't suit AI tooling.

How it's calculated

  1. Per-provider scoring

    Four factors are normalized against the org P90 cap and capped at 1.0, then weighted and summed to a 0–100 provider score.

  2. Union Claude and Codex into Primary

    The two are unioned at the factor level, not averaged. A developer using Claude in the morning and Codex in the afternoon gets credit for the combined daily spread rather than two fractional scores.

  3. Add the Cursor boost

    Cursor is scored independently and added to Primary at 25%. The total is capped at 100 before maturity scaling.

  4. Scale by Maturity Factor

    The final value is multiplied by the org's Maturity Factor. At the default 0.75, a developer at P90 on every factor scores 75 — leaving headroom to grow into the Power User band.

How to read it

  • 80–100Power User — integrated into daily work, multiple sessions per day
  • 55–79Regular — solid, consistent adoption; a routine part of the workflow
  • 25–54Explorer — using AI but not yet daily, or shallow integration
  • 0–24Emerging — minimal or no AI usage in the window

Tier bands are fixed reference points — they do not move with the Maturity Factor. What moves is the score, so at the default 0.75 the Power User band only opens up as you raise the factor toward 1.0.
